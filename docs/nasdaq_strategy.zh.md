# 纳指长期持仓策略设计

纳指模块面向长期 QQQ / Nasdaq 100 核心仓位。它先用价格趋势、波动和估值生成基础动作，再用事件/政策层做执行修正。

目标是保持被动指数仓位的长期稳定，同时避免在重大事件临近、短线拥挤或利率风险尚未确认时一次性追价。

## 基础仓位框架

基础动作由三类信号决定：

- 趋势：QQQ 相对 20 日、50 日、200 日均线的位置。
- 风险：VXN / VIX 和综合温度分数。
- 估值：Nasdaq 100 trailing P/E 和 forward P/E。

基础动作包括：

| 条件 | 基础动作 |
|---|---|
| QQQ 跌破 200 日线 | `防守` |
| QQQ 跌破 50 日线且 VXN 升温 | `小幅降仓` |
| 趋势健康但价格偏热、估值偏高 | `暂停加仓` |
| 趋势未破坏但市场恐慌 | `小幅加仓` |
| 趋势健康、波动平稳或中性 | `持有` |
| 信号不一致 | `持有` |

仓位调整只按 `step_allocation` 小步执行，不做清仓式择时。

## 事件层与执行约束

事件/政策层只修正执行节奏，不替代基础仓位框架。它的主要作用是限制追价和一次性加仓。

事件日历分成两个窗口：

- 展示窗口：继续使用 `lookahead_days` / `lookback_days`，用于在晨报中提示未来和近期事件。
- 执行窗口：只在事件临近或刚落地后的短窗口内覆盖动作，把 `持有` / `小幅加仓` 降为 `持有观察`。

常规宏观事件默认影响期较短：

| 类别 | 默认影响期 | 提前执行约束 |
|---|---:|---:|
| `增长` / GDP | 2 天 | 1 天 |
| `通胀` / CPI、PCE | 3 天 | 1 天 |
| `就业` / 非农 | 3 天 | 2 天 |
| `FOMC` | 5 天 | 3 天 |
| `财报` / 重点权重股 | 5 天 | 2 天 |

监管、地缘、科技监管、流动性等结构性冲击默认保留 14 天影响期。GDP/PCE 这类常规日历事件不应天然让仓位连续两周以上保持 `持有观察`；除非结果引发利率、VXN、趋势或指数广度的持续确认，才继续压制新增资金。

## 事件数据源

官方日历层只确定事件日期、类别和发布时间：

- Federal Reserve FOMC calendar
- BEA release schedule for GDP / PCE
- BLS CPI / employment schedule when available
- Nasdaq public earnings calendar
- `policy_events.csv` 手工兜底

官方数据层优先取一手或官方代理结果：

- FRED / BEA 序列用于 PCE、GDP 等宏观结果。
- 公司 IR / 官方新闻稿用于重点权重股财报。

媒体解释层只在官方结果阻塞时做临时 fallback：

- 优先选择 Reuters、WSJ、AP、CNBC、Bloomberg、MarketWatch、财联社、华尔街见闻等来源。
- 媒体结果必须显示“待官方校验”。
- 媒体结果只缓存 12 小时。
- 媒体结果不能直接把事件姿态升级为 `偏友好` / `偏谨慎`，也不能单独决定加仓或防守动作。

## 非周期事件发现

周期性事件和非周期事件采用不同刷新节奏：

- 周期性日历由晨报读取 `policy_calendar_cache.json`，常规低频刷新，事件落地前再校准。
- 非周期事件由独立发现器刷新 `policy_discovered_events_cache.json`，晨报只消费缓存，不在晨报生成路径里实时抓新闻。
- 手工高确信事件仍可写入 `policy_events.csv`，并优先于自动发现结果。

非周期事件发现器不是每日新闻搜索器，而是低频异步事件雷达。它适合由独立 cron 每周运行两到三次，目标是捕捉有发酵期、但不在官方宏观/财报日历里的重大催化，例如：

- 超大型 IPO、S-1、定价区间、定价日、Nasdaq 上市。
- Nasdaq 100 纳入、剔除、特殊再平衡等指数权重事件。
- AI / 半导体出口管制、反垄断、关税、科技监管。
- Treasury refunding、债务上限、政府停摆、流动性抽离等资金面冲击。
- AI 基础设施、半导体、云资本开支等可能改变盈利预期的产业事件。

发现器优先从高信噪比来源聚合标题和摘要，再按事件模式抽取，而不是只依赖单一实体关键词。SpaceX、OpenAI、Anthropic、Cerebras 等名称只是可能被抽取的对象，不应写死为策略前提。

候选事件按以下维度评分：

| 维度 | 作用 |
|---|---|
| 来源质量 | Reuters、Bloomberg、WSJ、FT、Axios、CNBC、Nasdaq、SEC、AP 等来源加分 |
| 明确日期 | 有定价日、上市日、文件日期、政策生效日时提高确认度 |
| Nasdaq / QQQ 传导 | 涉及 Nasdaq listing、Nasdaq 100、QQQ、指数资金或大型科技股时加分 |
| AI / 半导体相关性 | 涉及 AI、GPU、半导体、云和数据中心时加分 |
| 规模语言 | 涉及 billion / trillion、超大估值、巨额融资或被动资金流时加分 |
| 政策/流动性通道 | 影响监管约束、关税、出口许可、美债利率或美元流动性时加分 |

事件状态分层：

| 状态 | 晨报处理 |
|---|---|
| `confirmed` | 有明确日期且来源质量较高，进入重大事件日历 |
| `probable` | 有明确日期或多源确认，但仍需观察，进入重大事件日历 |
| `watch` | 处于发酵期但日期或传导尚不完整，只保留在发现缓存 |
| `expired` | 事件已过影响期或被新信息覆盖，不进入晨报 |

只有 `confirmed` / `probable` 且重要度达到 `discovery_min_importance` 的事件会合并进晨报事件日历。`watch` 事件用于后续升级，不直接约束仓位动作，避免把普通新闻噪声变成交易约束。

## 结果数据分层

事件结果使用 `result_source_tier` 标注：

| 层级 | 用途 |
|---|---|
| `official` | 官方或公司 IR 原始结果，优先级最高 |
| `official_proxy` | FRED 等官方代理序列，可用于正式策略姿态 |
| `media_confirmed` | 多家较高质量媒体转述一致，仅作临时摘要 |
| `media_single` | 单一媒体转述，只作短期提示 |
| `unverified` | 待校验 |

只有 `official` / `official_proxy` 结果可以影响政策姿态。媒体层结果只展示摘要和市场解读，不参与正式姿态升级。
